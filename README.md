# موقع صيدلية الدكتور علي عباس

موقع عربي متجاوب لصيدلية الدكتور علي عباس **في عين شمس الغربية، القاهرة**: بحث في دليل الأدوية المصرية، سلة وطلبات استفسار على واتساب، روابط مباشرة ومستقلة للأدوية، فهرس أبجدي، ومعلومات العنوان ومناطق التوصيل. يعرض صور العبوات الثماني المطابقة فقط ورسوماً موضّحاً أنها «تعبيرية» لبقية الأصناف. توجد صورة رئيسية **توضيحية لصيدلي رجل** وشعار هلالي.

- **عنوان مقر الصيدلية:** ٩١ امتداد شارع المشروع، عين شمس الغربية، القاهرة. [الموقع المثبّت على خرائط جوجل](https://maps.app.goo.gl/Pmdh7Nh8gGHSpTdh9).
- **مناطق يُستفسَر عن التوصيل إليها:** عين شمس الغربية، المطرية، عرب الحصن. **لا نعلن عن فروع في المطرية أو عرب الحصن.** تكلفة ووقت التوصيل بعد السؤال.
- **الدومين الأساسي المخصص لروابط الصفحات:** <https://dr-ali-abbas-pharmacy-site-14xz.vercel.app/>.

> **تنبيه مهم:** دليل الأدوية والأسعار مصدره بيانات خارجية **لا تمثل مخزون الصيدلية أو أسعار بيعها الحالية**. وجود صنف في الدليل أو ظهور زر الطلب لا يضمن توافره؛ الاستفسار عبر واتساب، ولا يُعد فتح الرسالة شراءً أو دفعًا أو تأكيد طلب. تحقّق مع الصيدلي من السعر والتوفر والروشتة المناسبة.

## التشغيل المحلي

المطلوب: Node.js **20.19+** أو **22.12+** وnpm. تأتي نسخة الدليل كاملة **داخل المشروع**، فلا يلزم اتصال بالإنترنت أثناء البناء (إنترنت مطلوب فقط لتنزيل الحزم وفتح خدمات واتساب/خرائط جوجل أو عند تحديث البيانات).

1. فك ضغط ZIP وافتح مجلد `pharmacy-site` (حيث `package.json`) في VS Code أو الطرفية.
2. شغّل:

   ```bash
   npm ci
   npm run dev
   ```

3. افتح العنوان الظاهر (عادةً `http://localhost:5173/`). تعمل صفحات الأدوية والفهرس في وضع التطوير وكذلك بعد البناء.
4. للتحقق من الاختبارات وبناء كل صفحات HTML وملف sitemap:

   ```bash
   npm test
   npm run build
   npm run preview
   ```

> لا يُضاف `node_modules` ولا `dist` إلى ZIP/GitHub عمدًا: يستعيد `npm ci` الاعتمادات، وينشئ `npm run build` كل ملفات النشر. **لا ترفع محتويات `dist` يدويًا بدل المصدر**؛ يجب أن يبنيها Vercel من المشروع.

## رفع المشروع إلى GitHub ثم Vercel

أنشئ مستودعًا فارغًا على GitHub، وارفع **محتويات** `pharmacy-site` حتى يصبح `package.json` في جذر المستودع. يمكنك تنفيذ `git init` والتقسيم إلى commits في Source Control ببرنامج VS Code ثم ربط المستودع و`git push`، أو:

```bash
git init
git add .
git commit -m "Build pharmacy catalog and SEO pages"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

إذا كان المستودع متصلاً بالفعل، **لا تعِد إنشاءه**: استخدم `git add .` و`git commit` و`git push` من المشروع الحالي. إذا رفعت مجلد `pharmacy-site` داخل المستودع بدل محتوياته، اجعل Root Directory على Vercel هو `pharmacy-site`.

في Vercel: **Framework Preset: Vite**؛ **Build Command: `npm run build`**؛ **Output Directory: `dist`**. ملف `vercel.json` يتضمن ذلك وإعداد الـ trailing slash للروابط. لا تستخدم قاعدة تحويل عامة `/(.*) -> /index.html`؛ ستُخفي صفحات الأدوية الفعلية. البناء يُنشئ عشرات الآلاف من ملفات HTML داخل `dist` من ملف JSON واحد مُدرج في المصدر؛ قد يتطلب هذا وقت نشر إضافيًا. رابط الإنتاج الحالي يستضيف نسخة سابقة إلى أن **تدفع التغييرات للمستودع المتصل وتتحقق من اكتمال نشر Vercel**؛ ZIP وحده لا يغيّر الموقع المنشور.

**تنبيه ترخيص الاستضافة:** وفق [سياسة Vercel](https://vercel.com/docs/limits/fair-use-guidelines#commercial-usage)، خطة Hobby مخصصة للاستخدام الشخصي غير التجاري، أما موقع الصيدلية التجاري فيتطلب خطة Pro أو Enterprise (أو استضافة أخرى تسمح بالنشاط التجاري). راجع الخطة الحالية قبل الإطلاق.

## SEO: الدومين، صفحات الأدوية وخريطة الموقع

- الصفحة الرئيسية: `<title>` ووصف وكود `Pharmacy` منظم مع **عنوان فعلي واحد** ورابط الخريطة ورقم الهاتف ومناطق الخدمة الحقيقية. لها canonical على الدومين النهائي أعلاه.
- صفحة `/delivery-areas/` تشرح العنوان والتوصيل إلى عين شمس الغربية والمطرية وعرب الحصن **من دون الادعاء بوجود فروع فيها**.
- تُنشأ صفحة HTML مستقلة لكل صنف صالح في نسخة الدليل (حاليًا **23,858 صفحة** من 25,070 سجلًا خامًا بعد استبعاد غير الصالح والمكرر و`(N/A)`). لكل صفحة عنوان وبيانات الصنف الأصلية ورابط canonical، وزر استفسار واتساب عن السعر والتوفر، وتحذير واضح من أن الدليل **ليس قائمة مخزون**. لا توجد علامة `Offer`/توافر/سعر بيع في البيانات المنظمة لأن الصيدلية لم تؤكد ذلك.
- `/directory/` وفهرس الصفحات التالية يربطان بجميع روابط الأصناف عبر روابط HTML حقيقية. بطاقات البحث في الصفحة الرئيسية تضع رابط «صفحة الدواء المستقلة». الصفحة الرئيسية في «الافتراضي» ما زالت تعرض **ثماني عبوات مصوّرة فقط**؛ يظهر كل الدليل بعد البحث أو «عرض كل الأدوية».
- `npm run build` يولّد `/sitemap.xml` ويضعه `public/robots.txt` على الدومين الصحيح. عدد عناوين الخريطة الحالية **23,908**: 23,858 صنفًا + 48 صفحة فهرس + صفحة التوصيل + الصفحة الرئيسية. الملف أقل من الحد البالغ 50,000 رابط/50MB.
- مثال لرابط مباشر بعد النشر: <https://dr-ali-abbas-pharmacy-site-14xz.vercel.app/medicine/panadol-extra-24-f-c-tabs-1wep1h0ewpmip/>. **تحقّق من هذه الصفحة ورابط `/directory/` و`/delivery-areas/` و`/sitemap.xml` على نطاق الإنتاج**: يجب أن ترجع 200 وتعرض محتواها، لا أن تُعيد الصفحة الرئيسية. صفحات غير موجودة يجب أن ترجع 404. الرابط الحالي قد يعطي 404 حتى تنشر الإصدار الجديد.

لتغيير النطاق لاحقًا، حدّث **`SITE_ORIGIN` في `src/config.ts` وcanonical/OG/schema في `index.html` ورابط sitemap في `public/robots.txt`**، ثم أعد البناء والنشر؛ لا تضع رابط نطاق مؤقت في Sitemap رسمي. إذا غيّرت خوارزمية الروابط في `src/lib/medicineUrl.ts` أو تغيّرت هوية صنف في المصدر فتذكّر إعداد تحويلات دائمة 301/308 للروابط القديمة المهمة ومتابعة 404 في Search Console.

### خطوات جوجل بعد النشر

1. بعد نشر الموقع الجديد على الدومين أعلاه والتأكد من أنه **متاح للعامة بلا حماية نشر أو `noindex`**، افتح [Google Search Console](https://search.google.com/search-console)، أضف خاصية **URL-prefix** `https://dr-ali-abbas-pharmacy-site-14xz.vercel.app/`، وتحقق من ملكيتها. **امتلاك Google Business Profile لا يعفي من تحقق Search Console المنفصل.** يمكنك وضع ملف تحقق HTML الذي تمنحك إياه Google داخل `public/` ثم commit/push/إعادة نشر قبل الضغط على Verify؛ احتفظ به لاحقًا. أو استخدم وسم التحقق داخل `<head>` في `index.html`.
2. أرسل في **Sitemaps** العنوان `https://dr-ali-abbas-pharmacy-site-14xz.vercel.app/sitemap.xml`. افحص الصفحة الرئيسية وصفحة التوصيل وعينة من صفحات الأدوية في **URL Inspection**، واطلب الفهرسة للصفحات الأهم؛ راقب تقارير Pages وsitemap بعد عدة أيام/أسابيع. لا تطلب يدويًا فهرسة آلاف الصفحات واحدةً واحدةً.
3. في **ملف النشاط التجاري المثبّت الذي تديره بالفعل**: حدّث خانة الموقع الإلكتروني بعنوان النطاق النهائي، وراجع الاسم والهاتف والعنوان الفعلي ونقطة الخريطة. أضف مناطق التوصيل الفعلية للمطرية وعرب الحصن وعين شمس الغربية **وفق خيارات جوجل المتاحة**؛ لا تضف عناوين فروع مزعومة.
4. لا توجد طريقة تقنية **تضمن ترتيبًا أولًا** عند البحث عن صيدلية في حي معيّن، أو فهرسة جميع صفحات الأصناف: جوجل يفصل بين الاكتشاف والزحف والفهرسة والترتيب، وقد يتجاهل صفحات دليل متشابهة/محتوى قليل القيمة. حافظ على بيانات دقيقة ومفيدة وحدّث معلومات الصيدلية أولًا، وراقب عدد الصفحات المفهرسة الفعلي بدل مساواته بعدد الروابط في الخريطة.

## مصدر الأدوية وتحديث النسخة

- مصدر البيانات العامة بترخيص **CC0**: [Egyptian Drug Database](https://github.com/karem505/egyptian-drug-database)، [ملف JSON الأصلي](https://raw.githubusercontent.com/karem505/egyptian-drug-database/main/data/egyptian-drugs.json). النسخة الموجودة في `public/data/medicines.json` التُقطت بتاريخ **2026-09-25** وتضم **23,858 صنفًا صالحًا**. تاريخ النسخة ليس تأكيدًا لسعر الصيدلية أو المخزون.
- تُحمّل النسخة المحلية من نفس النشر في المتصفح بدل الاعتماد على مصدر خارجي حي؛ لذا **تطابق روابط نتائج البحث صفحات HTML المولّدة**. يتم البحث والتصفية محليًا ويُعرض 12 صنفًا في كل دفعة. في حال تعذر تحميل النسخة، تظهر عينة احتياطية من 45 دواء وتنبيه واضح في `src/data/fallback-medicines.json`.
- لتحديث القائمة مستقبلًا: شغّل `npm run refresh:medicines` **باتصال بالإنترنت**، راجع تغييرات البيانات والأسعار/الأسماء، ثم `npm test && npm run build`، ثم commit/push للنسخة الجديدة. أمر البناء نفسه لا يجلب أدوية جديدة خفية. راقب الأصناف المحذوفة والروابط التي قد تتغيّر وتحقق من حقوق الصور.
- السلة محفوظة محليًا في `localStorage`. زر «شراء الآن» ينشئ رسالة عن صنف واحد، وسلة الطلب تنشئ رسالة بكل الأصناف والكميات، وكلاهما موجّه لرقم **01020345314**. زر «اطلب الروشتة عبر الواتساب» يرسل نص **«هل لديكم هذه الروشتة؟»**؛ **إرفاق صورة الروشتة يدوي** بعد فتح واتساب.
- صورة البطل في `public/images/pharmacy-hero-male.webp` توضيحية مولّدة وليست تصويرًا للصيدلية الفعلية؛ استبدلها بصورة تملك حقوق استخدامها إن رغبت.

## صور عبوات الأدوية

تظهر **صور عبوات للأصناف الثمانية المختارة فقط** في البطاقات وتفاصيل الصنف والسلة، مع مطابقة الاسم والتركيز وحجم العبوة لصفحة المصدر. تُحفظ نسخ WebP مضغوطة محليًا داخل `public/images/medicines/`، لذلك لا يعتمد عرضها على اتصال بمتاجر الصور. **الترتيب «الافتراضي» في الصفحة الرئيسية دون بحث أو تصنيف يعرض هذه الأدوية المصوّرة فقط.** لعرض جميع الأدوية اضغط «عرض كل الأدوية» أو اختر فئة «كل الأدوية»؛ ينتقل الترتيب إلى «حسب الاسم» حتى تكون القائمة الكاملة ظاهرة. وتظل بقية الأدوية متاحة أيضًا بالبحث والتصنيفات. إعادة اختيار «الافتراضي» بلا بحث أو تصنيف تعيد قائمة الأصناف المصوّرة.

إذا تعذّر تحميل الصورة، أو كان الدواء غير مشمول بالمطابقة **الحرفية** في `src/lib/productImages.ts`، يعرض الموقع رسماً عامًا يعبّر عن **الشكل الدوائي** (أقراص أو كريم أو شراب أو قطرات)، لا عن عبوة المنتج نفسها. يظهر معه وسم واضح «صورة تعبيرية — ليست صورة حقيقية لهذا الدواء»، وتنبيه أعلى نتائج البحث وفي تفاصيل المنتج والسلة؛ لا توجد صور حقيقية لبقية آلاف الأصناف. لا يُستخدم تصوير عبوة مختلفة لدواء مشابه (مثل 25 مجم بدل 50، أو 15 قرصًا بدل 10). قد يتغير شكل التغليف بمرور الوقت، ولا تعني الصورة توفر العبوة في الصيدلية.
